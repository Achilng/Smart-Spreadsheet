# React 前端重写计划

日期：2026-09-20。状态：规划完成，尚未安装依赖或开始迁移。

## 目标与设计方向

用户已确定使用 React 重写前端，并明确要求：以目前的结构为准，小修小改，保留现在的白色，允许调整细节。目标是改善控件品质、局部排版和操作反馈。第一份交付是沿用当前结构的可交互样稿，再逐步接入完整功能。

确定方向为白色界面的细节精修：沿用当前页面结构、功能入口、白底灰阶与蓝色强调色，改善中文排版、控件、局部留白和动效。参考花笺的细节一致性，不移植其暖纸色、竹绿色或页面布局。

- 导航：保留当前顶部的画廊、表格、素材、分组、重复项、提示词切换及前进后退；不改为左侧导航，不合并或重命名视图。
- 顶部：保留当前品牌、导航、搜索、工具箱、导入导出和窗口按钮位置，只微调尺寸、对齐、间距与窄窗口适配。
- 内容：保留当前 Tag / 筛选侧栏、内容区域、详情栏布局；统一卡片边缘、选中态、悬停操作、Tag 和版本入口的细节表现。
- 详情：沿用现有字段分节和编辑流程，改善标签与正文层次、按钮对齐、复制反馈和长文本阅读。
- 批量操作：沿用当前入口和出现时机，改进操作条排版，使处理数量和范围更清楚。
- 小窗口：保留当前 900×600 最小尺寸与现有适配方式，调整拥挤和截断问题；不主动增加新的抽屉式布局。
- 颜色：保留白色主界面和现有强调色；本轮不新增深色主题或主题切换。字号、字重、行高可微调，字体更换先在样稿中对照效果。

## 现状与迁移范围

规划基线：`1981ed4`，分支 `refactor/code-organization`。本地已安装程序见 PROGRESS.md。

当前有 79 个 `.svelte` 组件、31 个 `.svelte.ts` 模块。入口包含主窗口、工具箱、图片对比三个窗口。主窗口有画廊、表格、素材、分组、重复项、提示词文档；工具箱有 10 个工具。

| 部分 | 处理方式 |
| --- | --- |
| Tauri 2、Rust、SQLite、数据库 schema v20 | 沿用；重写阶段不改变数据库结构和后端行为 |
| `src/lib/api/` 的类型与 IPC 调用 | 复用，核对所有命令参数和返回值 |
| `images/` 的分级缓存、请求队列、布局计算 | 优先复用，替换 React 生命周期接入；验证资源释放 |
| `utils/` 的筛选、差异、导航等纯逻辑 | 复用现有测试；逐个检查依赖，不能把整个目录视为纯逻辑，例如 `empty-state.ts` 依赖旧 store |
| `windows/` 的事件协议与窗口操作 | 保留窗口 label、事件名和协议，重新接入事件监听 |
| `.svelte.ts` 状态与控制器 | 迁移到显式状态操作、React hooks 与页面控制器，保持业务语义 |
| 其它依赖旧 store 的 `.ts` 功能模块 | 一并解耦；不能只按照文件后缀确定迁移范围 |
| 页面、公共组件、全局 CSS、Svelte 动效 | 按新设计重做 |
| 现有功能与待发布功能 | 均进入迁移清单，以当前代码为准，不能仅对照最近发布版 |

## 技术方案

| 用途 | 选型与约束 |
| --- | --- |
| 应用 | React 19 + TypeScript + Vite，继续由 Tauri 承载 |
| 组件 | shadcn/ui，统一选择 Radix 基础组件路径；组件源码纳入项目，封装项目级控件 |
| 样式 | Tailwind CSS 4 + CSS 语义变量；沿用当前颜色，统一字体、间距、圆角、层次；覆盖组件默认主题以匹配现有界面 |
| 图标 | lucide-react，与当前图标体系衔接 |
| 状态 | Zustand 保存窗口内共享状态，组件内部使用 React state / reducer；按需订阅，避免整页跟随细小变化重绘 |
| 数据读取 | 先迁移既有按页缓存、查询代次和请求队列；同一结果集只保留一个缓存所有者，第一轮不叠加 TanStack Query |
| 大列表 | 先保留现有画廊布局算法；评估 TanStack Virtual 承担可见区计算，必须通过变宽、尺寸调整和返回位置测试才替换 |
| 编辑器 | 保留 Tiptap 文档格式与扩展行为，使用对应 React 接入方式 |
| 动画 | 优先 CSS 与组件基础交互；按需要引入动画依赖，图片滚动区避免逐卡片重型动画 |
| 页面切换 | 保留桌面窗口入口和现有浏览历史语义；视图状态用类型化导航管理，初期无需新增完整网站路由体系 |

实施前核对包版本、peer dependencies、现有 Node 兼容性及字体许可，锁定在 lockfile 中；不更新系统 Node 或其它环境组件。依赖缓存与临时产物优先放 D 盘，临时脚本和测试资料统一放 `D:\Agent\Agent_temp`。

## 状态与业务边界

- API 层只调用 Tauri 并返回数据；通知、导航、缓存刷新由业务操作组织。
- 区分资料库身份 / 数据版本、查询结果、窗口偏好、选择范围、任务进度、编辑草稿和通知。窗口间通过现有事件同步，不假设共享 JavaScript 内存。
- 搜索 / 筛选 / 排序 / 分页 / 导出使用相同查询快照；全选结果集与当前已加载页面不能混淆。
- 翻页和快速连续搜索保留请求代次校验；Tauri 请求即使无法真正取消，也不得把迟到结果写回新页面。
- 缓存键包含资料库身份、查询条件与版本；切库、迁移和重置必须失效缓存、图片 URL、浏览历史与选区。
- 编辑草稿归属于对应记录 / 页面；自动保存、失败重试、未保存离开提醒和关闭窗口保护独立实现。
- React StrictMode 开启；初始化、事件注册、异步卸载与图片 URL 释放必须可重复执行并正确清理。导入、写入、迁移和自动保存不能因 Effect 再运行而重复触发。
- 图库与素材复用基础画廊、详情框架、Tag 筛选和确认组件，各自保留搜索状态及业务操作；工具箱复用表单和步骤布局，不强行共用不同业务控制器。

## 迁移期间的工程策略

- 本次只交付计划，后续实施再创建专项分支；计划阶段不替换已安装程序。
- 结构、颜色和功能位置以上述用户要求为约束；发现需要大改布局的问题先记录，不以组件库默认样式或布局为理由扩大范围。
- 开发阶段使用独立 React HTML 入口和 Vite 配置，沿用同一后端；默认 Svelte 入口保留至验收完成。明确主窗口、工具箱、对比窗口各自的新入口映射。
- 新旧界面分开加载全局样式和运行时，不在同一组件树中混用两套框架；共用代码保持框架无关。
- 迁移验证使用复制资料库，不让新旧程序并发写同一测试库。回退通过旧构建与备份实现，不对用户工作目录执行破坏性重置。
- 不在迁移时同步引入新的数据库能力、改写 Rust 业务或增加大功能；发现原有问题单独记录，必要修复明确列出。
- 每完成一个可验收小目标，更新进度、提交并推送 GitHub。仅提交本任务文件，不包含现有未跟踪 `.claude/`。
- 完成验收后，在一次明确的收尾提交中移除旧 Svelte 源码、依赖和临时兼容入口。按本机删除规范执行；若任务受阻且需要删除超过 2 个文件，先征求用户批准。

## 功能核对清单

实施阶段将下列分组扩展为逐项记录；此清单用于避免遗漏，不表示已经验收。

- 启动与资料库：初始配置、已有目录、启动错误、后台补齐、目录迁移 / 重置、窗口控制与关闭保护。
- 导入：文件夹、压缩包、资源管理器拖入、更新现有图片、元数据解析与导入进度。
- 浏览：画廊 / 表格、缩略图与高清层、全屏图、尺寸调节、排序、搜索、结构化筛选、Tag、分组、重复项、前进后退与滚动恢复。
- 操作：详情字段与提示词编辑、复制、单选 / 多选 / 范围选择 / 全选、删除确认、撤销重做、资源管理器拖出完整原件。
- 导出：XLSX、智绘姬 JSON、轮询脚本 JSON、图片及对应选项，处理范围一致。
- 素材：库内 / 本地选图、元数据区域选取、封面、版本增删编辑与拖动排序、版本独立图片、默认复制、快速复制菜单、共享 Tag、草稿返回与失败重试。
- 提示词文档：新建编辑、图片导入、自动保存、切换文档、保存失败与关窗提醒。
- 工具箱：自动规则、快速整理、画师前缀修正、随机画师串、以图搜图、导出工具、智绘姬 JSON 去重、资料库维护、数据管理、应用更新。
- 图片对比：现有对比模式、样本与模型分区、原图查看、主窗口发起、资料库变更失效。

## 验收方法

### 视觉与操作

- 样稿必须包含长文件名、长提示词、多 Tag、无图、加载、空结果、错误和多选；同时使用真实代表图片与不同横竖比例，不能仅用整齐占位图判断效果。
- 新旧对照采用相同数据、窗口尺寸与页面状态；检查主要区域位置、导航顺序、入口和配色保持一致，并列出每项可见细节改进。
- 检查默认尺寸 1180×760、宽窗口 1440×900、最小 900×600，以及 Windows 125% / 150% 缩放；无整体横向溢出，表格允许局部横向滚动。
- 同级控件尺寸、字体、间距一致；主次操作明确；键盘可达、焦点可见、Esc 与焦点返回符合层级，输入法组合输入正常。
- 每个重要操作都有进行中、成功或失败反馈；失败后能重试，必要草稿与浏览位置保留；轻量动效遵循减少动态效果偏好。

### 行为与数据

- 沿用当前纯逻辑测试；类型检查改为 React 的 TypeScript 检查，补充迁移实际改变的缓存、选区、异步竞态和生命周期测试，不为简单样式逐条写测试。
- 扩展现有 DEV IPC mock 支持新入口与故障场景，浏览器覆盖主流程；原生文件对话框、拖入 / 拖出、跨窗口事件、窗口关闭和真实导出必须在 Tauri 上单独实测。
- 覆盖连续搜索、请求乱序、切库时在途请求、筛选后全选导出、跨页操作、多窗口编辑、自动保存失败与离开页面等关键场景。
- 构建与现有 Rust 回归全部执行；旧数据用副本打开，核对图片 / 素材 / 版本 / Tag / 分组 / 文档，不因换框架触发数据库升级。

### 性能

- 在同一机器、同一复制资料库上比较旧版与 React 版：冷 / 热启动、首次出现可用图片、搜索结果稳定时间、连续滚动、详情打开和稳定内存。
- 覆盖小库与至少一万条记录；优先使用代表性大库副本，构造数据需标明限制。分别记录渲染和真实 IPC 耗时。
- 每个时间指标至少测 5 次，以中位数比较；规划目标是关键时间指标和稳定内存相对基线不恶化超过 10%，异常超标先定位再验收，不把噪声当结论。
- 渲染节点随可视区域变化，不随全库条目数增长；连续切页 / 切库后监听器与图片 URL 无持续累积。
