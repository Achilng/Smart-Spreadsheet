## 组织规则

| 部分 | 职责 |
| --- | --- |
| 页面和组件 | 展示、输入与局部交互；调用所属功能的业务操作 |
| 前端业务模块 | 按功能组织状态、操作、撤销和刷新流程 |
| 公共 UI、图片和工具模块 | 已被多个入口使用的基础能力，避免反向依赖页面和全局状态 |
| API 与窗口通信 | IPC 封装、消息协议与窗口导航 |
| 后端命令 | 参数接收、阻塞任务调度、进度事件与结果转换 |
| 后端运行时 | 资料库生命周期、连接访问；功能入口按业务拆分 |
| 规则业务模块 | 规则模型、校验、匹配与动作计算 |
| 数据库与文件存储 | SQL、事务和文件读写，保留既有事务边界 |

具体目录和修改入口见 [ARCHITECTURE.md](ARCHITECTURE.md)。

按职责拆分，不以行数作为验收标准。移动实现时保留原有行为；相似算法存在差异时，只提取语义相同的部分。已知业务缺陷另列后续任务，避免混入结构调整。

## 阶段（均已完成）

1. 建立回档基线、检查现有测试和构建状态。
2. 后端命令与运行时按功能组织，保留 IPC 协议。
3. 拆分规则引擎、快速整理和导入内部职责，分离已有测试。
4. 收拢前端通知、任务、资料库状态与公共工具，建立清楚的依赖方向。
5. 抽取重复能力并迁移调用点，将大型页面中的业务状态和操作移到所属功能模块。
6. 清理过渡入口、检查依赖，运行完整验证并更新架构说明。

## 保留的边界

本次保持业务行为和数据格式。审查中发现的后台任务互斥、筛选条件修改后的缓存失效、跨窗口编辑通知和不同入口选择范围一致性等潜在行为问题，需单独复现和修复；不作为结构重构顺带改动。仍较长的查询实现或包含大量布局 / 样式的组件，也不按行数机械拆分。
