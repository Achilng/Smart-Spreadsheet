# 内置 LLM 提取

## 使用入口

完整工作台位于「工具箱 → LLM提取」，包含提取任务、渠道设置、复用白名单、JSON 导入 / 导出。主窗口只在右上角显示文字进度，不增加画廊按钮、右键操作或人工批改入口。

1. 在「渠道设置」添加渠道，填写名称、Base URL、API Key、完整模型名与并发数。Base URL 填到 /v1，不附加 /chat/completions；支持获取模型列表后搜索选择。保存后即可使用。
2. 在「提取任务」选择全部资料库、主窗口选中图片或当前筛选结果，勾选参与渠道。统计会列出可直接复用、等待已有任务、仍需提取的正文数量；点击「开始后台处理」。纯复用任务无需配置渠道；有缺失结果时才需要可用渠道。
3. 任务独立于导入、浏览和整理操作运行。关闭工具箱不停止；退出软件停止调用并保留进度。完成结果严格校验后自动应用，失败保持旧值，成功的「无画风」会清空旧画师串并保留 LLM 来源。
4. 任务记录中可暂停、继续、结束、重试失败项、查看原文高亮与实时输出、导出 JSON。暂停或完成后可撤销本任务写入；后续发生变化的图片保留现状。撤销记录保存在资料库中，关闭工具箱或重启后仍可使用。

## 自动行为

- **导入图片时自动提取**：默认关闭。开启后，在图片导入与已有自动规则完成之后，将本次新增图片加入队列；不会扫描并自动重跑全部历史图片。
- **默认继续未完成工作**：默认开启。打开对应资料库后恢复关闭软件或异常退出中断的任务。手动暂停、结束和需要修复配置的任务不自行恢复；关闭开关后，未完成任务等待手动继续。
- 正向正文按复用白名单匹配：空格和下划线等价（连续出现视为一个分隔），忽略名单内的完整标签（包括数值、花括号、方括号权重包裹）、空标签与末尾逗号；其余内容、权重和顺序仍参与比较，不拼接角色提示词。`soft shading` 与 `soft_shading` 相同，`softshading` 仍不同。无法安全解析的权重语法保持逐字匹配，避免错误合并。
- 匹配后的相同内容跨任务、导入和重启复用历史成功结果，包含成功的无画风结果、旧 JSON 导入结果和旧提取提示词版本的有效结果。切换模型 / 渠道不触发重提；失败、无效结果不复用。
- 在途和同批匹配正文只安排一条模型输入，其它条目等待结果后复用。任务保留各自原文；复用结果映射到目标原文中的连续片段，保存目标自身的原文哈希，保留撤销与冲突保护。
- 仅明确勾选「强制重新提取（忽略历史结果）」才绕过历史缓存；该任务内部的相同内容仍共享一次新提取。失败项允许重试。
- 默认仅更新创建任务时的图片范围。勾选「同时更新全库匹配正文的图片」才扩展到忽略白名单后匹配的图片；创建后导入的新图片单独保留任务记录并共享已有提取结果。
- 同一图片及正文已有未完成任务时不重复入队。正文或画师串在任务创建后发生变化、图片被删除时跳过写回，并保留原因。

## 复用白名单

在「工具箱 → LLM提取 → 复用白名单」按行编辑并保存，可恢复默认值。空格与下划线写法自动归一、去重，旧名单也会自动合并；默认仅含批准的 A 类词，合并后为 8 项：

```text
very aesthetic
no text
masterpiece
best quality
amazing quality
absurdres
the image is very aesthetic
highres
```

年份、newest、细节强度、rating:general、location、official art、artist collaboration、no signature 等 B/C 类词均未加入。只匹配完整标签，不会把 dark aesthetic 等风格词误删。白名单同时用于 LLM 正文复用和画师串归类，不改原始提示词或已保存的画师串；保存新名单后，已有画风归类自动重算，后续提取按新规则匹配历史结果。

详情面板、表格、对比样本与 LLM 任务结果中的画师串，会用柔和橙色高亮已保存白名单里的标签。鼠标悬停或键盘聚焦时显示「这些tag会在比较画师串时被忽略」。历史结果同样生效，保存白名单后自动刷新，无需重新调用 LLM。高亮使用实际比较时的同一解析器，支持空格 / 下划线、大小写及数值 / 花括号 / 方括号权重；无法安全解析的权重语法保持原文比较，也不高亮。文字、权重、顺序和复制内容均保持原样。

## 刷新已有画风归类

入口位于「工具箱 → LLM提取 → 复用白名单 → 刷新画风归类」。按已保存的规则检查整个资料库，显示检查图片数、归类变化及刷新前后的有效画风数，不调用模型。首次升级会自动整理，平时新增 / 编辑 / 应用 LLM 结果 / 撤销均自动维护；需要手动重算时点击刷新即可。

- 「只看当前画师串」「选中相同画师串」、按画师串去重、重复项的画师串相册、画师串代表图，以及对比窗口的“相同画师串”统一使用 `rows.artist_match_key`。
- `prompt_matching` 是唯一的解析与归一化实现，数据库函数通过现有 rusqlite / SQLite 能力调用它。LLM 的输入是完整正向提示词，画风归类的输入是画师串，两者共享规则而不混用标识。查询使用持久索引，不在每次浏览时扫描并解析全部文本。
- 原始字段、历史 LLM 结果和手动分组不变；权重及顺序差异仍会分开。只有品质词、无剩余有效内容时，不将这些图片合并成一个画风。对比窗口中按完整提示词 / VIBE 建立的其它关系仍保持原有含义。
- 合并后的画风若已有多个代表图，保留图片编号最小的一张；原图片均保留。重复项名称优先使用已有的归一化名称，否则按原键字典序取一项；其它原名仍保存在库中。手动清空名称后，刷新不会恢复已清空的旧名称。
- 历史提取结果若在归一化后仍有实质差异，此功能保留各自结果，不擅自选择其中一份覆盖其他图片。

## 渠道与请求

- 本机直接调用自定义 OpenAI 兼容 /chat/completions 接口，不使用工作台服务器，也不需要安装 Node 或 Codex CLI。API Key 仅发送至对应渠道，不发送图片，仅发送正向正文和固定提取提示词。
- 配置、两个开关和 Key 随资料库保存。Key 以明文保存在本地资料库中，不再绑定 Windows 账户，复制资料库到其他电脑后可继续使用；界面只显示是否已保存，不将 Key 带入任务、导出结果或日志。更改端点时清空旧 Key。旧版加密 Key 会在原电脑、原 Windows 用户下打开资料库时自动转为本地保存；若已迁移到无法解密的环境，原加密值会保留，需要重新填写一次。
- 多渠道共享一个任务的待处理队列，各自独立并发，默认每渠道 1，不设固定并发上限。任务顺序排队；运行中保存渠道配置会影响后续调用，在途请求继续使用原参数。任务页的「应用渠道选择」修改当前任务参与渠道。
- 默认每次调用 10 条，支持 1–100；按正文长度自动缩小批次，单条正文不截断。推理等级可选低 / 中 / 高。明确拒绝结构化输出、推理等级或流式参数的兼容接口会移除对应参数后重试。
- 网络或结果校验错误最多尝试三次，仅重试未完成项。限流按接口等待时间或递增间隔恢复；连续三轮仍限流则停用该渠道，等待用户继续或调整配置。授权、权限、额度或模型错误停用对应渠道，其它渠道继续领取未完成项。
- 流式输出为尚未校验的预览，完整响应中的每条结果独立检查与保存。未知、缺失、重复编号或非连续原文仅使对应条目失败。界面实时请求每页最多展示 40 个，不限制执行并发。

## 持久化与一致性

- 数据库 v24 新增 llm_jobs / llm_items，v25 补齐开发期统计字段，v26 增加 LLM 复用索引，v27 增加共享画风匹配列、索引及自动维护触发器。任务保存正文、目标图片及原字段快照，结果保存实际模型与渠道；升级保留既有任务、结果、撤销记录和设置。计数随结果事务更新，进度刷新不重复全表统计正文。
- 每条结果的写回、撤销记录和完成状态在同一 SQLite 事务中提交，避免重启后重复应用。暂停取消所有在途请求，已完成条目保留；持久化失败停止继续发起调用。
- 后台执行不占用前端全局忙碌状态；数据库锁只用于短时读写，不跨网络请求。主窗口按节奏刷新结果并保留选区，有编辑草稿或前台任务时延后刷新。
- 任务绑定资料库标识及目录，切换、重置、迁移后旧请求不能写入其它资料库。应用与撤销都检查正文和字段快照，避免覆盖用户后续修改。
- 正向正文变化后 LLM 标记失效，角色、负向、备注和 Tag 的修改不影响提取结果。随机画师池继续沿用已有的逗号拆分与权重补全规则。

## JSON 兼容与历史工具

保留 request v1 / result v1 的导出、预览和导入，稳定 ID 仍为正向原文 UTF-8 SHA-256。兼容导入保留原有规则：匹配当前资料库全部相同正文，预览后由用户应用，支持窗口历史撤销。

旧网页工具源码与部署记录保留，桌面端不再提供独立网页入口。本次内置不包含 Codex CLI 或人工批改；旧工具说明见 [外置工作台](../tools/style-extractor/README.md)。
