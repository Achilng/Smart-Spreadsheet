# 服务器工作台

提取与批改是两个独立的 Node HTTP 服务，均绑定回环地址，由 Nginx 提供 HTTPS。当前按用户要求免登录，共享任务及批改数据。模型调用由提取服务访问服务器上的 CLIProxyAPI。朋友的电脑只需要浏览器，关闭网页不会停止任务。

## 提取服务

- 入口：`style-extractor/server.mjs`。
- `STYLE_PORT`：默认 17321。
- `STYLE_DATA_DIR`：任务与结果的持久目录。
- `STYLE_PUBLIC_ORIGIN`：网站完整 HTTPS 来源，不带路径或尾部斜线。
- `STYLE_SERVER_API_BASE`：启用固定接口模式，不允许客户端修改调用地址或切回服务器 Codex。`STYLE_API_PUBLIC_BASE` 为网页展示及浏览器凭据匹配的公开地址。
- API Key 仅由浏览器 localStorage 按接口地址保存，获取模型列表或开始任务时通过 HTTPS 临时提交。服务器不提供凭据存取、不读取 `STYLE_SERVER_API_KEY`、不写入任务或日志；部署时应删除旧环境变量及其副本。服务建议设置 `LimitCORE=0`，避免内存凭据进入进程转储。
- 网页保留模型选择、批次大小、并发、推理等级、暂停、续跑和结果下载。模型默认 gpt-6-luna。

关闭浏览器不取消任务，Key 在任务执行期间仅保留于服务器进程内存；服务重启后不自动调用模型，需要用户返回网页，由浏览器回填 Key 后点击「开始 / 继续」。已完成结果持续保存；SIGTERM 等待请求取消和结果落盘。服务由 systemd 开机启动、失败自动重启，但不会从磁盘恢复调用凭据。

重启时尚未收到完整结果的调用可能重新请求并产生额外用量；已经保存的成功结果不重复处理。额度不足、授权失效等错误仍需解决后手动继续。

## 批改服务

- 入口：`style-review/server.mjs`。
- `STYLE_REVIEW_PORT`：默认 17324。
- `STYLE_REVIEW_ORIGIN`：网站完整 HTTPS 来源。
- `STYLE_REVIEW_DATA_DIR`：设置后启用服务器保存；未设置则保留本机只读服务模式。

批改原始结果、判定、备注、参考答案和当前位置单独存盘，不修改模型结果。网页显示“已保存到服务器”后才代表服务器确认。保存失败时保留当前浏览器备份并重试；新设备可从服务器历史选择记录。多个页面提交时按每条记录更新时间合并，旧页面不会覆盖较新的判定。

## 反向代理与权限

当前部署按用户明确要求关闭提取 / 批改网站的 Basic Auth（两个站点设置 `auth_basic off`），无需网站账号密码；任何访问者均可访问共享任务、结果及批改数据。后端回环服务不承担公网用户认证，会话 token 仅用于请求校验，不提供用户隔离。浏览器 localStorage 仍按接口保存 API Key，调用时须显式提交，服务器没有默认 Key 兜底。CPA 管理接口鉴权、模型接口鉴权及 Codex OAuth 登录保持不变。

保持 Host 为网站域名，关闭 proxy_buffering，上传上限 64 MB，读取超时至少 600 秒。不要将明文密码、API Key 或账号文件提交到仓库。

服务采用独立低权限系统用户，代码只读，数据目录可写。备份持久数据及受保护配置。HTTPS 证书自动续期，续期后重新加载 Nginx。

## 智能表格入口

工具箱只打开服务器网页，不启动本机 Node。点击“服务器地址”可修改两个 URL；设置仅保存在当前电脑。

构建时可在未提交的 `.env.local` 中设置 `VITE_STYLE_EXTRACTOR_URL` 和 `VITE_STYLE_REVIEW_URL` 作为默认地址。发布包不再携带网页工具程序或本机运行环境。开发版使用这些默认值，正式安装版需要另行重新构建安装。

原来本机的任务、Key 和浏览器批改记录不会自动上传。已有结果可以直接导入服务器批改台；本机批改记录应先导出 JSON，再导入服务器，以保留原判定和备注。
