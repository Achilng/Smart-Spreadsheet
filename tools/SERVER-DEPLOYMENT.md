# 服务器工作台

提取与批改是两个独立的 Node HTTP 服务，均绑定回环地址，由 Nginx 提供 HTTPS。当前按用户要求免登录，共享任务及批改数据。模型调用由提取服务访问用户选中的一个或多个接口，包含服务器上的 CLIProxyAPI。朋友的电脑只需要浏览器，关闭网页不会停止任务。

## 提取服务

- 入口：`style-extractor/server.mjs`。
- `STYLE_PORT`：默认 17321。
- `STYLE_DATA_DIR`：任务与结果的持久目录。
- `STYLE_PUBLIC_ORIGIN`：网站完整 HTTPS 来源，不带路径或尾部斜线。
- `STYLE_SERVER_API_BASE`：启用服务器模式，禁止调用服务器 Codex CLI；保留原 CPA 默认连接。`STYLE_API_PUBLIC_BASE` 是该连接的公开别名，网页提交此地址时仍转到原服务器接口。其他渠道可使用自定义公网 HTTPS 地址，不允许自定义渠道访问私网、回环、链路本地地址或跟随重定向；DNS 校验位于实际 HTTPS socket 的 lookup 中。
- API Key 仅由浏览器 localStorage 按独立渠道编号保存，获取模型列表或开始任务时通过 HTTPS 临时提交。服务器不提供凭据存取、不读取 `STYLE_SERVER_API_KEY`、不写入任务或日志；部署时应删除旧环境变量及其副本。服务建议设置 `LimitCORE=0`，避免内存凭据进入进程转储。
- 网页 `/channels` 独立管理名称、地址、Key、模型、并发和启用状态；`/` 用于选渠道和执行任务。并发没有固定上限，按实际待处理批次数调度。运行中应用渠道调整仅影响后续请求。

关闭浏览器不取消任务，Key 在任务执行期间仅保留于服务器进程内存；服务重启后不自动调用模型，需要用户返回网页，由浏览器回填 Key 后点击「开始 / 继续」。已完成结果持续保存；SIGTERM 等待请求取消和结果落盘。服务由 systemd 开机启动、失败自动重启，但不会从磁盘恢复调用凭据。

重启时尚未收到完整结果的调用可能重新请求并产生额外用量；已经保存的成功结果不重复处理。额度不足、授权失效等错误只停用对应渠道，其他渠道继续处理。所有渠道不可用时保留未完成项并暂停；解决配置后手动继续。

## 批改服务

- 入口：`style-review/server.mjs`。
- `STYLE_REVIEW_PORT`：默认 17324。
- `STYLE_REVIEW_ORIGIN`：网站完整 HTTPS 来源。
- `STYLE_REVIEW_DATA_DIR`：设置后启用服务器保存；未设置则保留本机只读服务模式。

批改原始结果、判定、备注、参考答案和当前位置单独存盘，不修改模型结果。网页显示“已保存到服务器”后才代表服务器确认。保存失败时保留当前浏览器备份并重试；新设备可从服务器历史选择记录。多个页面提交时按每条记录更新时间合并，旧页面不会覆盖较新的判定。

## 反向代理与权限

当前部署按用户明确要求关闭提取 / 批改网站的 Basic Auth（两个站点设置 `auth_basic off`），无需网站账号密码；任何访问者均可访问共享任务、结果及批改数据。后端回环服务不承担公网用户认证，会话 token 仅用于请求校验，不提供用户隔离。浏览器 localStorage 按渠道保存 API Key，调用时须显式提交，服务器没有默认 Key 兜底。CPA 管理接口鉴权、模型接口鉴权及 Codex OAuth 登录保持不变。

保持 Host 为网站域名，关闭 proxy_buffering，提取 / 批改站点设置 `client_max_body_size 0;` 取消固定上传大小限制，读取超时至少 600 秒。不要将明文密码、API Key 或账号文件提交到仓库。

服务采用独立低权限系统用户，代码只读，数据目录可写。备份持久数据及受保护配置。HTTPS 证书自动续期，续期后重新加载 Nginx。

## 智能表格入口

工具箱只打开服务器网页，不启动本机 Node。点击“服务器地址”可修改两个 URL；设置仅保存在当前电脑。

构建时可在未提交的 `.env.local` 中设置 `VITE_STYLE_EXTRACTOR_URL` 和 `VITE_STYLE_REVIEW_URL` 作为默认地址。发布包不再携带网页工具程序或本机运行环境。开发版使用这些默认值，正式安装版需要另行重新构建安装。

原来本机的任务、Key 和浏览器批改记录不会自动上传。已有结果可以直接导入服务器批改台；本机批改记录应先导出 JSON，再导入服务器，以保留原判定和备注。

## 多渠道版本部署

更新整个 `style-extractor` 代码目录中的源文件及网页资源（尤其是新增的 `channels.mjs`、`channel-runner.mjs`、`public-fetch.mjs`、`channels.html`、`channels.js`、`channel-store.js`、`workspace.js`、`app.css`），保持数据目录和服务环境不变。无需安装新依赖或升级 Node。部署前备份现有程序及任务数据；尽量在没有任务运行时重启提取服务。若需中断任务，先等待暂停完成，已保存条目不会重跑，重启后由浏览器重新提供 Key。

检查 `/health`、`/`、`/channels` 和上述静态资源响应正常，确认历史任务仍可读取。原版按地址保存的浏览器 Key 自动迁移为独立渠道，原 CPA 公网地址仍映射到原服务连接。不在部署脚本、命令行参数或仓库中保存 SSH 密码 / API Key。

## 2026-10-03 简化使用页

生产环境设置 `STYLE_CHANNEL_CONFIG=/etc/style-tools/extractor-channels.json`，管理员在服务器编辑此文件；权限 0640、root:style-tools；上层 `/etc/style-tools` 为 root:style-tools、0710，允许服务用户进入但不能列出目录。当前默认 codex、原 CPA 地址、gpt-6-luna、20 并发、每批 20 条、high。配置修改在下次创建 / 开始任务时读取，无需重启；需要改变运行中任务时先暂停后继续。Key 仅在此受保护配置文件与运行内存中，不返回网页或写入任务数据。

启用时，用户页面只上传、开始、暂停 / 继续、取消与下载；渠道页面和修改接口关闭，不接受用户传入的渠道配置。此前关于浏览器 Key 的说明适用于未设置此变量的开发者模式。取消会中止在途请求并等待退出，然后删除任务状态及上传文件，清除内存预览；已取消任务不会恢复，暂停则仍保留结果。

## 大任务增量保存（2026-10-04）

更新 `core.mjs`、`channel-runner.mjs`、`server.mjs` 时一并部署 `result-journal.mjs`。新增每任务 `.results.jsonl` 是已确认结果的一部分，备份整个任务数据目录；不能只复制 `.json`。每条增量同步落盘，每 5 秒 / 暂停 / 完成生成全量检查点，检查点写成功后才清空增量。进程中断时启动会重放增量，按 ID 合并或撤销，不重复计数。若回滚旧版程序，先由新版正常暂停并汇总结果，避免旧版无法读取未汇总增量。

生产 `batchSize` 已调整为 20；新建和继续同一任务均读取管理员配置，不需要重新上传，模型与渠道不变。
