# 外置画风提取工具

1. 在智能表格「工具箱 → LLM 画风提取」导出待处理 JSON。可选全部、选中或当前筛选范围；原文完全相同才合并，默认跳过已处理记录。
2. 点击智能表格「工具箱 → 画风网页工具 → 画风提取工作台」，在默认浏览器打开服务器网站，无需网站登录，无需填写渠道或 API Key。开发者仍可双击本目录的 `启动画风提取.cmd`，或运行 `node tools/style-extractor/server.mjs` 使用本地模式。
3. 服务器使用简化页面：选择待处理 JSON，点「上传并开始」即可。后台默认使用管理员配置的 codex / gpt-6-luna 渠道。暂停保留结果，可继续；「取消任务并丢弃结果」经确认后停止请求，并删除该任务的原始上传、结果和历史记录，无法继续。完成的任务也可用此按钮清理。
4. 完成后下载结果 JSON，在智能表格同一工具页预览并应用。相同原文的全部记录一起更新，表格和详情显示 LLM 标记，支持撤销 / 重做。

## 服务器默认配置

服务器通过 `STYLE_CHANNEL_CONFIG` 指定管理员配置文件。生产路径为 `/etc/style-tools/extractor-channels.json`，仅 root 和服务用户可读（0640，root:style-tools）；不要提交到 Git。文件包含 `channels`（id、name、baseUrl、apiKey、model、concurrency、enabled）、`batchSize` 与 `effort`。每次创建 / 开始任务重新读取，修改后用于后续启动，在途请求保持原配置。浏览器不能覆盖这些设置，`/channels` 和配置接口关闭，Key 不返回浏览器、不写入任务文件。简化模式无需浏览器提供 Key，服务重启后仍需手动继续。

未设置此环境变量时，保留下面的开发者多渠道页面与浏览器凭据模式；本地默认地址 http://127.0.0.1:17321 。

## 渠道管理与混跑（开发者模式）

「提取工作台」和「渠道管理」（`/channels`）是两个独立页面。渠道管理左侧选择渠道，右侧只编辑一个渠道，避免大量配置挤在提取页。

- 每个渠道独立设置名称、Base URL、API Key、模型和并发请求数，可启用、停用、删除或清除 Key。
- 支持不同 Base URL，也支持同地址多个 Key。不同渠道可以使用不同模型，或同一模型在不同接口上的不同名称。
- 模型可手动填写，也可点击「获取模型列表」后搜索和选择；修改接口或 Key 后清空过期列表。更改地址时清空当前 Key，避免把旧凭据发送给新接口。
- 并发为正整数，不设 32、100 等固定上限。总并发为所选启用渠道的并发之和；配置容量再大，也只为实际待处理批次创建请求。实际吞吐取决于接口额度、服务器、网络和磁盘能力；同一账户的多个 Key 可能共享额度。
- 所有渠道共享一份待处理队列，有空位就领取下一批，快渠道自然处理更多。正常执行不会重复分配同一条目，已校验成功的结果不重跑。

服务器同一时间运行一个任务；查看其他任务时，顶部会显示正在运行的任务，并提供「查看运行中的任务」和「暂停运行中的任务」。暂停后可以继续另一个任务，已保存结果不会清除。

提取页左侧的渠道选择用于**新任务**；右侧「本任务参与渠道」用于**已有任务**。开始 / 继续 / 重试时采用右侧所选渠道的最新配置。旧单渠道任务也可以选择多个渠道续跑，已保存结果保留。

运行中可以去渠道管理添加渠道、修改 Key / 模型 / 并发或停用渠道，然后回到提取页点击「应用渠道调整」。已有请求使用原来的参数继续完成，后续分配使用新参数；减少并发时先等待多出的请求自然结束。全部渠道停用后，在途请求完成，剩余条目保留，任务暂停。点击「暂停」则会取消所有在途请求。

渠道摘要显示本轮状态、在途请求 / 配置并发、成功条数及失败尝试条数。失败尝试可能包含后来重试成功的条目。请求详情默认折叠，每页最多展示 40 个请求槽位，仅限制展示数量，不限制执行并发。结果 JSON 每条增加 `channel_id`、`channel_name` 和 `model`，顶层 `processor.model` 汇总实际结果使用的模型；原有智能表格和批改台仍可读取。

## 接口和凭据

自定义 API 使用 OpenAI 兼容的 `/chat/completions`，Base URL 填到 `/v1`，无需附加 `/chat/completions`。线上允许配置公网 HTTPS 接口；原有服务器 CPA 地址继续可用，服务内部仍使用已配置的连接。自定义渠道不能访问服务器内网地址，DNS 解析和实际建连时均受约束，不跟随接口跳转。本地模式也允许本机 HTTP 接口用于开发测试。

渠道配置和 Key 按**渠道编号**分别保存在当前浏览器 localStorage，同地址多个 Key 不会互相覆盖。首次打开自动将旧版按地址保存的 Key 转为渠道；空渠道列表不会再次迁移旧 Key。换浏览器或设备需重新填写，无法读取配置时会报错，不会自动覆盖已有数据。

Key 只在获取模型列表、开始任务或应用运行中调整时临时传给后端，运行期间仅留内存；任务文件、结果、日志、Git 和其他浏览器无法读取这些凭据。「清除 Key」或删除浏览器配置不终止已发出的调用，需要停止调用时请暂停任务。关闭网页继续运行，服务器重启后回网页重新开始 / 继续，由浏览器提供 Key 后只续跑未完成条目。

CLIProxyAPI 也是一个普通渠道：Base URL 填 HTTPS 代理地址，Key 填代理的客户端访问密钥。不要填写服务器 SSH 密码或 OAuth 凭据。部署配置和数据迁移说明见 [服务器工作台](../SERVER-DEPLOYMENT.md)。

支持 low / medium / high 推理等级。若兼容接口明确拒绝结构化输出或推理等级参数，会去掉对应参数重试，并仍严格校验返回的 JSON、编号与连续原文。

「Codex CLI · 本机登录」模式使用 `gpt-6-luna`，复用本机 ChatGPT 登录和订阅额度，不需要 API Key。选择该模式、导入待处理 JSON、创建新任务后开始即可；每批条数、并发、进度保存与 API 模式相同。

Windows 按以下顺序选择 CLI：手动设置的 `STYLE_CODEX_BIN` → PATH 中桌面应用自带的 `codex.exe` → 本机桌面安装目录中最近更新的 CLI → PATH 中的独立 / npm 安装。自动查找版本目录，不写死用户名或版本文件夹，不修改系统 PATH 或升级环境。调用日志显示实际 CLI 路径。

2026-09-24 排查确认：同一账号的 npm CLI 0.153.4 报 Luna 不支持，而桌面自带 0.155.0-alpha.9.2 成功；后者使用 v2 提示词单批 3 条约 11.7 秒完成并与预期逐字一致。此前报错不能推断账号没有 Luna 权限。若仍被拒绝，先核对日志中的 CLI 路径及当前账号模型权限；不会自动改用 API 或其他模型。小样本不代表全库准确率。

## 模型编号

每次请求只给模型短编号 `"1"`、`"2"`…，返回后由程序映射回原文的稳定 ID。SHA256 仍用于导出、去重和表格导入匹配，不再发给模型抄写。并发请求和重试各自使用独立映射，返回顺序不影响配对；未知编号仅影响缺失条目，已通过校验的条目保留。提示词版本未变化的任务可直接「重试失败项」，无需重新导出。

## 当前提示词

完整内容见 `prompt.txt`，当前版本为 `style-extraction-v2`。根据人工批改加强空行分段：下一人物段开头的质量词不再并入画风；同段画师前后的水彩、水墨、线稿、黑白等整体保留。保留 upper body 等主体描述前截断的规则，并补充同段泛称及风格化倾斜构图的边界示例。第 62 条已由用户确认为提取正确，第 64 条待定样本不用于改规则。

提示词在服务启动时加载；更新后重启服务，使用原待处理 JSON 创建新任务即可采用 v2。v1 历史结果仍可下载，不能在旧任务中混用新提示词。这次修改依据已有反馈，尚未通过真实模型复测准确率。

## 进度与恢复

每个渠道并发默认为 1，不设固定上限。10 并发表示最多同时发出 10 个模型请求；若每次 10 条，则最多有 100 条同时处理。每条完整结果通过校验即独立保存，不必等待整批返回，返回顺序不影响结果与原文的对应。

界面显示累计运行时间（不含暂停）、进度、批调用次数、正在进行的请求数、无画风和失败数量。结果逐条保存到本目录 `data/`，请保留它；关闭网页不停止任务。输入与进度分开保存，避免频繁重写整份正文。服务只监听 127.0.0.1。

展开请求详情后使用两列紧凑请求槽位，每页最多显示 40 个；每条返回时更新片段，校验通过后推进小进度格与计数。点击通道，在下方唯一的详情区查看原文高亮及提取文本；默认跟随当前输出，也可选择本批中的某条。流式片段标明“尚未确认”，只有完整且校验通过的条目计入成功。等待模型输出时不模拟读取进度，窄屏自动改为单列，并尊重系统减少动画设置。

API 请求启用 `stream: true` 并读取 SSE；兼容接口明确拒绝流式参数或直接返回普通 JSON 时，会注明整批等待后校验。Codex 使用桌面 CLI 的 `app-server` 文本增量事件，每次调用建立临时、只读会话，复用已登录账号。两种方式保持相同的 v2 提示词、每次独立短编号和原文校验。2026-09-24 各用同一组 3 条小样本实测，均收到 28 次片段预览和 3 条完整结果事件，API 约 8.4 秒、Codex 约 16 秒完成；这验证流式通路，不代表全库提取准确率。

浏览器通过实时连接接收通道状态，断线后自动重连并补齐当前快照；刷新网页不影响后台任务。临时片段只保存在运行服务的内存中，服务重启后不会恢复未完成片段，但已通过校验的结果仍保留。断流或输出截断仅重试尚未完成项；同一编号重复返回时撤销该条先前结果并重试，避免任意选用其中一份。

点击暂停会取消所有正在进行的调用，等待它们退出后才能继续；各批未保存的条目在继续时重新请求。关闭服务或电脑后重新启动，选择历史任务继续；成功项不重跑。网页短暂断线会自动重连，服务重启后网页自动刷新恢复任务列表。每批数量为上限，长正文批次会自动缩小，单条不截断。

多渠道模式下，网络错误和内容校验失败对尚未完成条目最多尝试三次；限流按 Retry-After 或递增等待恢复，同一批并发限流响应只计一轮，界面显示等待倒计时；同渠道连续三轮恢复尝试仍限流后停用至下一次开始 / 应用调整。授权、权限、额度或模型不存在会停用对应渠道，未完成条目交给其他可用渠道，不取消其他渠道的在途请求。所有渠道均不可用时暂停并保留进度；正在等待限流恢复的渠道会在等待结束后重试。本机 Codex CLI 仍使用原有全任务暂停行为。失败项可单独重试，也可下载已完成部分；失败 / 未处理项导入时保持表格旧值。成功的「无画风」结果会清空旧值并保留 LLM 标记。修改正向正文后标记失效，角色 / 负向 / 备注的修改不影响它。提示词变更后旧任务禁止继续，以免混用规则；仍可下载旧结果或创建新任务。

待处理文件、桌面端结果导入和批改台导入不设固定文件大小上限，仍校验 JSON 格式及内容；大文件的实际处理能力取决于可用内存。可选环境变量：`STYLE_PORT`（默认 17321）、`STYLE_DATA_DIR`（任务保存目录）、`STYLE_TEMP_DIR`（CLI 临时目录，默认 D:/Agent/Agent_temp/style-extractor）、`STYLE_CODEX_BIN`（Codex 可执行文件路径）。测试临时目录与正式 data 分开。

验证：`node --test tools/style-extractor/*.test.mjs tools/style-review/*.test.mjs`。多渠道测试覆盖独立容量、超过 32 并发、同址不同 Key、混合模型、失败转移、限流恢复、运行中调整、旧 Key 延迟报错、暂停续跑、流式部分结果、凭据不落盘和分页快照。

## 大任务结果保存

多渠道 API 每条校验成功后，先把新增结果追加到同任务的 `.results.jsonl` 增量文件并同步落盘，再更新页面；重复的流式 / 整批确认不会重复写入。每 5 秒以及暂停、完成时，将结果汇总到任务 `.json`，成功后清空增量文件，避免每条都重写整份大文件。启动时自动合并尚未汇总的增量记录，最后一条未写完的记录不会被当作成功结果。备份时需同时保存 `.json`、`.request.json` 和 `.results.jsonl`。

服务器默认每次调用最多处理 20 条，仍保留长正文自动缩批、单条原文不截断；继续已有任务也读取管理员设置的批大小，已完成项不重跑。取消会同时清理任务增量文件。
