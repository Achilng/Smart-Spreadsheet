# 外置画风提取工具

1. 在智能表格「工具箱 → LLM 画风提取」导出待处理 JSON。可选全部、选中或当前筛选范围；原文完全相同才合并，默认跳过已处理记录。
2. 点击智能表格「工具箱 → 画风网页工具 → 画风提取工作台」，在默认浏览器打开服务器网站，无需网站登录。不需要在本机安装 Node；首次使用填写 API Key，保存在当前浏览器。开发者仍可双击本目录的 `启动画风提取.cmd`，或运行 `node tools/style-extractor/server.mjs` 使用本地模式。
3. 浏览器打开 http://127.0.0.1:17321 ，选择 JSON 和「自定义 API」。填写 Base URL、模型名、API Key，设置每次调用条数（默认 10）和并发请求数（默认 1），创建任务后点「开始 / 继续」。
4. 完成后下载结果 JSON，在智能表格同一工具页预览并应用。相同原文的全部记录一起更新，表格和详情显示 LLM 标记，支持撤销 / 重做。

## 接口设置

工具箱已改为服务器网页入口，不再依赖本机 Node。服务器任务与结果持久保存，关闭网页不影响运行，服务重启后需回到网页点击「开始 / 继续」，浏览器重新提供 Key 后续跑未完成条目。部署配置、认证和数据迁移说明见 [服务器工作台](../SERVER-DEPLOYMENT.md)。以下接口配置说明适用于开发者手动启动的本地模式。

CLIProxyAPI 也使用「自定义 API」模式：Base URL 填自己的 HTTPS 代理地址并以 `/v1` 结尾，Key 填代理的客户端访问密钥。先在代理端完成 Codex 登录，再获取模型列表；只有模型实际可用时才能开始提取。不要把服务器 SSH 密码或 OAuth 凭据填到 API Key。

需要本机已有 Node（支持内置 fetch / AbortSignal.any，例如当前 Node 24），不安装或升级环境。自定义 API 使用 OpenAI 兼容的 `/chat/completions`；Base URL 填到 `/v1`，无需附加 `/chat/completions`。

本次默认接口 `https://oneapi.hakoyu.com/v1` 的模型列表实际返回 `gpt-6-luna【神秘】`，请使用完整名称，包括后缀。Base URL 与模型名均可自行修改。2026-09-24 已通过该模型名真实调用：用户原始 3 个示例逐字一致，另一次单批 10 条（原始 3 条加 7 条小样本）全部通过原文校验并与预期一致，用时约 11 秒。小样本不代表整个资料库的识别准确率，也不验证第三方底层模型身份。

模型旁的「获取模型列表」使用当前 Base URL 和 Key 请求 `/models`，支持直接使用当前接口已保存的 Key。获取后可搜索并点选模型，完整名称自动回填；「刷新模型列表」重新读取接口。切换 Base URL 或输入新 Key 会清空旧列表，过期请求不会覆盖新列表。接口不支持列表、返回空列表或读取失败时仍可手动填写。列表用于新建任务，已有任务的模型保持不变；Codex 模式仍固定使用 gpt-6-luna。

API Key 按 Base URL 分别保存在当前浏览器的 localStorage；不写入服务器环境变量、任务 JSON、日志或 Git。填写后离开输入框会自动保存，也可以点击「保存 Key」；启动 API 任务前也会保存。重新打开网页或切换历史任务会自动回填对应接口的 Key。「清除已保存 Key」只清除当前浏览器当前接口的凭据，不影响正在运行的任务；若需停止调用，请先暂停任务。换浏览器或设备需重新填写。保存失败会显示错误。旧版本 Windows DPAPI 文件不会自动迁移或读取，可从原来保存的渠道重新填写。

当前 Key 下方会显示适用的 Base URL。切换接口后清空旧输入并读取该接口已保存的 Key；运行历史任务时按该任务实际端点匹配，不会把另一个接口的 Key 直接用于它。创建后端点和模型固定，左侧参数用于新任务；已有任务可以修改右侧并发数后开始 / 继续 / 重试。原文发送至所选端点，由该接口账户计费。获取模型列表或开始任务时，Key 临时发送给后端用于调用；任务期间仅保留在内存，关闭网页可继续，服务重启后需再次由浏览器提供。

支持 low / medium / high 推理等级。若兼容接口明确拒绝结构化输出或推理等级参数，会去掉对应参数重试，并仍严格校验返回的 JSON、编号与连续原文。

「Codex CLI · 本机登录」模式使用 `gpt-6-luna`，复用本机 ChatGPT 登录和订阅额度，不需要 API Key。选择该模式、导入待处理 JSON、创建新任务后开始即可；每批条数、并发、进度保存与 API 模式相同。

Windows 按以下顺序选择 CLI：手动设置的 `STYLE_CODEX_BIN` → PATH 中桌面应用自带的 `codex.exe` → 本机桌面安装目录中最近更新的 CLI → PATH 中的独立 / npm 安装。自动查找版本目录，不写死用户名或版本文件夹，不修改系统 PATH 或升级环境。调用日志显示实际 CLI 路径。

2026-09-24 排查确认：同一账号的 npm CLI 0.153.4 报 Luna 不支持，而桌面自带 0.155.0-alpha.9.2 成功；后者使用 v2 提示词单批 3 条约 11.7 秒完成并与预期逐字一致。此前报错不能推断账号没有 Luna 权限。若仍被拒绝，先核对日志中的 CLI 路径及当前账号模型权限；不会自动改用 API 或其他模型。小样本不代表全库准确率。

## 模型编号

每次请求只给模型短编号 `"1"`、`"2"`…，返回后由程序映射回原文的稳定 ID。SHA256 仍用于导出、去重和表格导入匹配，不再发给模型抄写。并发请求和重试各自使用独立映射，返回顺序不影响配对；未知编号仅影响缺失条目，已通过校验的条目保留。提示词版本未变化的任务可直接「重试失败项」，无需重新导出。

## 当前提示词

完整内容见 `prompt.txt`，当前版本为 `style-extraction-v2`。根据人工批改加强空行分段：下一人物段开头的质量词不再并入画风；同段画师前后的水彩、水墨、线稿、黑白等整体保留。保留 upper body 等主体描述前截断的规则，并补充同段泛称及风格化倾斜构图的边界示例。第 62 条已由用户确认为提取正确，第 64 条待定样本不用于改规则。

提示词在服务启动时加载；更新后重启服务，使用原待处理 JSON 创建新任务即可采用 v2。v1 历史结果仍可下载，不能在旧任务中混用新提示词。这次修改依据已有反馈，尚未通过真实模型复测准确率。

## 进度与恢复

并发数可设 1–32，默认 1；旧任务也默认 1。10 并发表示最多同时发出 10 个模型请求；若每次 10 条，则最多有 100 条同时处理。每条完整结果通过校验即独立保存，不必等待整批返回，返回顺序不影响结果与原文的对应。

界面显示累计运行时间（不含暂停）、进度、批调用次数、正在进行的请求数、无画风和失败数量。结果逐条保存到本目录 `data/`，请保留它；关闭网页不停止任务。输入与进度分开保存，避免频繁重写整份正文。服务只监听 127.0.0.1。

实时工作区使用两列紧凑通道，10 并发占五行；每条返回时更新片段，校验通过后推进小进度格与计数。点击通道，在下方唯一的详情区查看原文高亮及提取文本；默认跟随当前输出，也可选择本批中的某条。流式片段标明“尚未确认”，只有完整且校验通过的条目计入成功。等待模型输出时不模拟读取进度，窄屏自动改为单列，并尊重系统减少动画设置。

API 请求启用 `stream: true` 并读取 SSE；兼容接口明确拒绝流式参数或直接返回普通 JSON 时，会注明整批等待后校验。Codex 使用桌面 CLI 的 `app-server` 文本增量事件，每次调用建立临时、只读会话，复用已登录账号。两种方式保持相同的 v2 提示词、每次独立短编号和原文校验。2026-09-24 各用同一组 3 条小样本实测，均收到 28 次片段预览和 3 条完整结果事件，API 约 8.4 秒、Codex 约 16 秒完成；这验证流式通路，不代表全库提取准确率。

浏览器通过实时连接接收通道状态，断线后自动重连并补齐当前快照；刷新网页不影响后台任务。临时片段只保存在运行服务的内存中，服务重启后不会恢复未完成片段，但已通过校验的结果仍保留。断流或输出截断仅重试尚未完成项；同一编号重复返回时撤销该条先前结果并重试，避免任意选用其中一份。

点击暂停会取消所有正在进行的调用，等待它们退出后才能继续；各批未保存的条目在继续时重新请求。关闭服务或电脑后重新启动，选择历史任务继续；成功项不重跑。网页短暂断线会自动重连，服务重启后网页自动刷新恢复任务列表。每批数量为上限，长正文批次会自动缩小，单条不截断。

临时失败最多尝试三次；登录、权限、额度或限流错误会取消其余请求并暂停整个任务，保留已保存结果，解决后继续。失败项可单独重试，也可下载已完成部分；失败 / 未处理项导入时保持表格旧值。成功的「无画风」结果会清空旧值并保留 LLM 标记。修改正向正文后标记失效，角色 / 负向 / 备注的修改不影响它。提示词变更后旧任务禁止继续，以免混用规则；仍可下载旧结果或创建新任务。

待处理文件、桌面端结果导入和批改台导入不设固定文件大小上限，仍校验 JSON 格式及内容；大文件的实际处理能力取决于可用内存。可选环境变量：`STYLE_PORT`（默认 17321）、`STYLE_DATA_DIR`（任务保存目录）、`STYLE_TEMP_DIR`（CLI 临时目录，默认 D:/Agent/Agent_temp/style-extractor）、`STYLE_CODEX_BIN`（Codex 可执行文件路径）。测试临时目录与正式 data 分开。

验证：`node --test tools/style-extractor/core.test.mjs tools/style-extractor/browser-credentials.test.mjs tools/style-extractor/streaming.test.mjs`。
